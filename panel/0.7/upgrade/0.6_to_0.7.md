# 從 0.6 升級至 0.7

::: danger 此版本已終止支援
本文件適用於**已終止生命週期的軟體**，不再提供任何安全性更新或社群支援。
基於歷史原因，本文件仍保留供查閱。

在正式環境中，你應安裝並使用 [Pterodactyl Panel 1.0](/panel/1.0/getting_started.md)。
:::

## 取得更新檔案
更新流程的第一步，是從 GitHub 下載新的 Panel 檔案。下方指令會下載最新 Pterodactyl 版本的發行壓縮檔，並儲存到
目前目錄。這裡要提醒一下，執行前請先確認自己位於 `/var/www/pterodactyl`，因為下方指令會直接把壓縮檔解到目前
所在的目錄。

::: warning 警告
由於我們僅提供最新版本文件的翻譯，通常只有依照我們的文件說明操作、或使用我們的一鍵安裝程式，才會套用我們的繁體中文化版本。若你選擇安裝舊版本，即代表你將安裝官方的英文版本，我們將不提供翻譯內容上的支援；但技術問題仍可透過 [Discord](https://pterodactyl.tw/discord) 與我們聯絡，或與其他使用者討論翻譯相關問題。
:::

``` bash
curl -L https://github.com/pterodactyl/panel/releases/download/v0.7.19/panel.tar.gz | tar --strip-components=1 -xzv
```

下載完所有檔案後，還需要幫快取與儲存目錄設定正確的權限，避免之後跑出跟網頁伺服器有關的錯誤。

``` bash
chmod -R 755 storage/* bootstrap/cache
```

## 清除已編譯資源
早期版本的 Pterodactyl 曾嘗試把設定檔快取起來，希望能提升速度與效能，但實際上帶來的麻煩比好處還多，效能改善也
很有限，所以後來這個做法就停用了。執行下方指令會清掉那些快取檔案，這樣我們才能繼續往下升級。

::: tip 提示
如果是從 `0.6.X` 升級，這一步通常只需要做一次。升級完成之後，設定檔就不會再被快取，所以之後就不用再重複這個步驟。
:::

``` bash
rm -rf bootstrap/cache/*
```

清掉設定快取之後，接著還要清除範本快取，確保使用者看到的是最新的範本。

``` bash
php artisan view:clear
```

## 更新相依套件
新檔案都下載完成後，接下來要更新 Panel 的核心元件。執行下方指令，並依照畫面上的提示操作即可。

``` bash
composer install --no-dev --optimize-autoloader
```

## 更新環境設定
執行下面這些指令時，畫面上的方括號會顯示目前的值。如果想保留原本的設定，直接按 Enter 跳過就好，流程會繼續進行，
不會動到既有設定。

::: tip 提示
這裡順帶一提，我們已經把建議使用的快取驅動程式從 Memcached 改成了 Redis。如果你目前用的還是 Memcached，
其實可以繼續正常使用，只是之後的安裝文件會統一改成只說明 Redis 的做法。
:::

``` bash
php artisan p:environment:setup
php artisan p:environment:mail
php artisan p:environment:database
```

## 更新資料庫

::: warning 備份資料庫
從 `0.6` 升級到 `v0.7` 這一步，牽涉到相當大幅度的資料庫結構變更。雖然遷移工具會幫你把大部分工作處理好，
但穩妥起見，還是建議在繼續之前先備份一次資料庫，以防萬一出狀況。
:::

::: warning 警告
要特別注意，執行下方的 `db:seed` 會覆寫掉你對 Pterodactyl 核心 Nest、Egg 或 Egg 變數所做的任何修改！
這一點無法避免，而且這個 Seeder 是必須執行的步驟。如果想避免未來再遇到同樣的問題，建議改為建立自訂 Nest，
或是替遊戲變體另外建立自訂 Egg。
:::
``` bash
php artisan migrate --force
php artisan db:seed --force
```

## 清理 API 金鑰
0.7.0 版對 API 金鑰的使用、儲存與驗證方式做了重大變更，因此，先前建立的所有金鑰都會直接失效，無法繼續使用。
為了保持整潔，建議移除這些已經失效的孤立金鑰，執行下方指令即可完成。

``` bash
php artisan p:migration:clean-orphaned-keys
```

別忘了幫自己建立一組新的金鑰，也記得通知所有使用者同樣要建立新金鑰。

## 設定權限
最後一步，是把檔案擁有者設定成執行網頁伺服器的那個使用者。大多數情況下會是 `www-data`，不過實際情況可能因系統
而異，有時候會是 `nginx`、`apache`，甚至是 `nobody`。

``` bash
# 使用 Nginx 或 Apache（CentOS 除外）：
chown -R www-data:www-data * 

# 在 CentOS 上使用 Nginx：
chown -R nginx:nginx *

# 在 CentOS 上使用 Apache：
chown -R apache:apache *
```
